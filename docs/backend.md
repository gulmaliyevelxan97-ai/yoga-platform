# Проект серверной части Yoga Space

## Граница текущего выпуска

GitHub Pages раздаёт общедоступные файлы. Профиль, таймер, черновики и флажки плана принадлежат браузеру. Любой статический файл доступен по адресу. Оплаченные видео и ключи в репозиторий не помещают. Гость может изучать программы и проходить открытые занятия. Даты и места поступят из расписания преподавателя.

## Авторизация и данные

Предлагаемая конфигурация — Supabase Auth, Postgres, закрытое объектное хранилище и серверные функции. Альтернатива — отдельный API и Postgres с управляемым поставщиком идентификации. Подключение, регион данных и условия хранения согласуются с владельцем. Проект провайдера пока не создан.

Сервер проверяет сеанс пользователя. На таблицах прикладных данных включаются RLS и запрет доступа по умолчанию. Разделение полномочий задаётся на сервере. У гостя есть публичный каталог. Пользователь видит только свой профиль, прогресс, заявки и покупки. Premium — ограниченное по сроку право доступа, совместимое с любой ролью. Преподаватель управляет своим контентом и слотами и видит только необходимые сведения о записавшихся. Администраторы получают отдельное назначение, MFA и журнал действий. Публичный JS не выдаёт ролей. Ключ с правами обслуживания хранится только на сервере. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

| Сущности | Ключевые поля и правила |
| --- | --- |
| profiles, role_assignments | auth_user_id, display_name, locale. Назначения изменяет авторизованный администратор. |
| teachers, teacher_specialties | Публичный slug, биография и фотографии с переводами, связь с учётной записью. Статус публикации. |
| courses, modules, lessons, media_assets | Автор, стабильные ID, порядок, уровень, переводы, версия, вид доступа. Временные подписанные URL для защищённого медиа. |
| practice_events, favorites, plans | Владелец и уникальный client_event_id. Прогресс принадлежит одному пользователю. |
| slots, bookings | Преподаватель, UTC-время, часовой пояс, вместимость, статус. Уникальная активная запись участника на слот. |
| offers, orders, subscriptions, entitlements | Идентификатор предложения, цена в минимальных единицах, валюта, срок. Цена и валюта задаются сервером. |
| provider_events, audit_log | Уникальное событие провайдера, обработанный результат, субъект и время административной операции. |

### Перенос локального прогресса

Существующие ключи yogaspace.session.*, yogaspace.favorite.*, yogaspace.language и yogaspace.request.* сохраняются. Новые настройки имеют префикс yogaspace.v1. После входа предложить человеку импорт с этого устройства. Передавать события с исходным стабильным ID, а настройки — с версией. Повторный импорт дедуплицировать по (user_id, client_event_id). Разрешать конфликт настроек по версии и выбору пользователя. Локальные события никогда не доказывают оплату, принадлежность к персоналу или факт бронирования. После выхода отделять кеши учётных записей.

## Бронирования и видеосвязь

GET /slots выдаёт только опубликованные слоты, клиент отображает время в часовом поясе посетителя. POST /bookings требует сессию, slot_id и ключ идемпотентности. Транзакция блокирует строку слота, проверяет вместимость, отсутствие конфликта и условия доступа. Сервер возвращает статус pending или confirmed. POST /bookings/{id}/cancel проверяет владельца, правила отмены и освобождает место один раз. Изменения пишутся в историю. Пока работающий интерфейс хранит предпочтения и отмену локальных черновиков.

После подтверждения бронирования отдельный серверный процесс создаёт комнату выбранного видеопровайдера. Только участнику и преподавателю выдаётся короткоживущая ссылка перед занятием. Отмена отзывает доступ. Секреты комнат и списки участников не публикуются в Pages.

## Оплата и подписки

Для азербайджанского продавца кандидатами являются Epoint и PASHA Bank. Epoint описывает приём местных и иностранных карт, повторяющиеся платежи, работу с ИП и юрлицами. PASHA Bank предлагает интернет-эквайринг, регулярные платежи и возвраты. До выбора запросить актуальные договоры, валюты расчёта, международные ограничения, комиссии, тестовую среду и формат подтверждения событий. Наличие API и точные его возможности сверяются с договором и документацией выбранного провайдера. [Epoint](https://www.epoint.az/az/faq) · [PASHA Bank](https://www.pashabank.az/en/kob-sme-elektron-ticaret)

1. POST /checkout принимает ID предложения. Сервер сам определяет сумму и валюту, создаёт pending-заказ и направляет клиента на защищённую форму провайдера. Данные карты пользователь вводит у провайдера.
2. Обработчик уведомлений проверяет подлинность по спецификации провайдера, защиту от повтора, ID продавца и заказа, сумму, валюту и конечный статус. При необходимости сверяет состояние через серверный API. Повторное событие не создаёт повторную покупку.
3. После подтверждения одна транзакция записывает событие, оплаченный заказ и право доступа. Возврат из формы оплаты не подтверждает покупку. Повторные платежи продлевают подписку; возвраты и споры обрабатываются отдельными событиями.
4. POST /subscriptions/{id}/cancel проверяет владельца и синхронизирует отмену с провайдером. Срок доступа зависит от оплаченного периода и утверждённой политики. Периодическая сверка исправляет пропущенные уведомления.
5. Перед выпуском проверьте успешную и неуспешную оплату, повтор вебхука, несовпадение суммы, возврат, отмену, просроченное право и одновременные запросы. До согласования цен, валют и условий никаких реальных транзакций.

## Администрирование и ввод в эксплуатацию

Закрытый интерфейс редактора должен поддерживать черновик → проверку прав на материалы → публикацию версии, управление преподавателями, программами, расписанием и предложениями. Сервер авторизует каждую операцию, ведёт журнал и запрещает преподавателю изменять чужие записи. Агрегировать статистику с минимальным набором персональных данных. Открытая админ-панель отсутствует.

Порядок запуска: согласовать владельца данных и условия → развернуть отдельную тестовую среду → включить Auth, миграции, RLS и резервное копирование → проверить права разных аккаунтов, гонки за одно место и восстановление → подключить загрузку видео → провести тестовые оплаты и возвраты → разрешить боевой приём заявок и платежей только после отдельного решения владельца.

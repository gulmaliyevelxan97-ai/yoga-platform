# Готовность RESTART 2.0 к закрытому пилоту

| Область | Критерий |
| --- | --- |
| Регрессии | Node, проверочная сборка пилота, целостность медиа и аудит зависимостей |
| Бронирование | Два независимых соединения PostgreSQL и одна подтверждённая запись на последнее место |
| Приложение | Обе темы, три языка, прямые ссылки, обновление кеша и офлайн-дневник |
| Supabase Auth | Действующий hook, разрешённый тестовый адрес, получение письма, вход, выход и восстановление |
| Данные | Изоляция двух учеников, импорт и синхронизация с двух устройств |
| Samsung | Установка, открытие с главного экрана, работа без сети и обновление |

Production остаётся закрытым до согласования владельцем. Для проверки с реальным Supabase нужны закрытый HTTPS-стенд, разрешение на создание тестовых аккаунтов и отправку писем. Результаты локальных тестов подтверждают поведение кода с тестовыми данными.

## Результат интеграционной проверки

- 71 тест Node прошёл, включая локальные проверки PKCE, политик доступа, упаковки PWA и регрессии.
- Верификационная сборка SDK прошла. Аудит npm вернул 0 известных уязвимостей на момент проверки.
- PostgreSQL 16.16 на временной базе с тестовыми Auth-ролями принял девять миграций. Два независимых соединения конкурировали за последнее место. Второе дождалось блокировки, получило отказ, итоговая запись одна.
- В Chromium проверены четыре мобильных размера, три языка, установка по manifest и офлайн-дневник. Проверка реального устройства остаётся отдельным этапом.
- Все 24 исходных объекта в `assets/` совпадают с базовой версией.

## Закрытый пилот 6.0

Исходная проверенная интеграция: `18fc1e8ec857a45fb8a236ffbe4c5158f6b88c44`. Снимок действующего сайта для восстановления: `b98336a34a2882414372bbc96d784773d5759366`. Тесты привязываются к коммиту сборки. При изменении кандидата повторите регрессии и ручные сценарии затронутых модулей.

1. Владелец согласует отдельный HTTPS-стенд, изолированный Supabase и два контролируемых тестовых адреса. Сверьте URL возврата для `/app/`, почту и включение Auth Hook. В CI или журнал результата передавайте только идентификатор сборки и исход сценария.
2. На изолированной базе примените миграции в порядке версий. Запустите [проверку облачной схемы](../supabase/checks/installed_cloud.sql) и [проверку школьной схемы](../supabase/checks/installed_school.sql). Каждая строка должна иметь `ok = true`. Установка hook через Dashboard и отправка писем проверяются отдельно.
3. Проверьте отказ адреса вне списка, получение письма и смену пароля, вход, выход, изоляцию, обновление данных между устройствами, повторный импорт после удаления, бронирование последнего места и восстановление черновиков после потери сети. Начинайте каждую почтовую проверку в том же профиле, где будете открывать ссылку.
4. На физическом Samsung пройдите [сценарий установки, обновления и офлайн-запуска](samsung-pwa-test.md). Зафиксируйте модель, Android, браузер, SHA, исход каждого шага и воспроизводимое описание дефекта.
5. После прогона на стенде повторите проверочную сборку и тесты на финальном SHA. При дефекте остановите допуск пользователей и верните предыдущую сборку стенда. Схему базы рассматривайте отдельно: восстановление фронтенда не откатывает миграции и данные.

Критерий допуска первых участников — прохождение пунктов 1–4 с ожидаемыми результатами. Публичный выпуск дополнительно требует согласования владельца и проверенного плана восстановления приложения и базы.

### Локальные результаты кандидата 6.0

- Node: 78 успешных тестов, 0 ошибок и пропусков. Проверочная сборка прошла. Аудит зависимостей вернул 0 известных уязвимостей.
- Браузер: 360, 375, 390 и 430 px, три языка, офлайн-дневник. Отдельный сценарий обновления проверил отказ при повреждённой сборке, ожидание активации, отмену и принятие обновления, изоляцию кешей и повторный офлайн-запуск.
- PostgreSQL 16.16: свежая база приняла миграции 001–011. Прошли 10 облачных и 33 школьных проверки каталогов и прав. Тестовые роли подтвердили решения Auth Hook, исключение владельца из числа учеников, ограничение медиа уроков и одну запись при двух параллельных транзакциях.
- Все оригинальные медиа совпадают с действующей веткой. Видеоссылки открываются у внешнего провайдера. Доступ к самому видео определяется настройками провайдера.

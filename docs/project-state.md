## Архитектура и реализованные функции

- Статический сайт на HTML, CSS и JavaScript. Генератор `releases/navigation/build.py` собирает 12 страниц и список ресурсов service worker. Сборка требует Python 3, тесты используют Node.js без зависимостей времени выполнения сайта.
- Первая неделя включает семь дней, 28 заданий, дневник и отчёт. Видны цели недель 2–8, материалы этих недель предстоит подготовить.
- Каталог объединяет занятия с таймером, программы и бесплатную видеотеку. Встроенный видеоплеер и обложки зависят от YouTube. Таймер, отметки, настройки, избранное и дневник сохраняются в браузере.
- Личный раздел показывает локальные данные. Для защищённого аккаунта ученика нужен сервис идентификации и серверное хранилище с изоляцией данных. [Проект серверной части](backend.md)
- Ветка `deploy/restart-telegram` на `d2f179d` содержит приветствие, ссылки, программы, RU/AZ/EN, напоминания с согласием, SQLite и конфигурацию Render. Все 10 тестов прошли без токена. Фактическое развёртывание и доставка напоминаний требуют отдельной проверки.

## Журнал кандидата

- Сохранены все фотографии, публичные маршруты и ключи локальных данных. Из «О RESTART» добавлен прямой переход к существующему профилю основателя и его фотографиям.
- Исправлены ссылки с отметок недельного отчёта на соответствующие дни. Добавлена проверка сохранения отметки после повторной загрузки и сохранения языка.
- Добавлена ссылка пропуска навигации на страницах школы, локализованы названия навигационных областей, меню закрывается клавишей Escape и при нажатии вне него. Уточнены отступы и кнопки для экранов до 380 px.

## Синхронизация панели и кабинета

Перенос задач между устройствами выполняется экспортом JSON. Импорт объединяет данные и сохраняет варианты расходящихся задач и контрольных точек. Общедоступный репозиторий годится как источник статусов сборки и истории. Запись персональных заметок или профилей в него раскрыла бы их. Техническая основа для будущей синхронизации — приватный серверный сервис с авторизацией владельца, изолированными записями, версиями для обнаружения конфликта и экспортом. Учётные данные и выбор среды остаются отдельным решением. Для переноса прогресса ученика используйте стабильные ID и правила из [серверной архитектуры](backend.md).

## Следующее действие и порядок выпуска

Первый сценарий на Android — открыть опубликованный RESTART, выбрать первый день, отметить задание, обновить страницу и перейти к этому дню из недельного отчёта. У текущей публикации ссылка отчёта известна как проблемная. Для сравнения используйте сборку кандидата на компьютере в той же сети или отдельно согласованный тестовый адрес.

Перед выпуском:

1. Сверьте HEAD рабочей ветки, резервную точку и SHA опубликованной версии.
2. Выполните `python3 releases/navigation/build.py`, `node --test tests/*.test.cjs` и `git diff --check`. Для тестирования подпапки подавайте локальную копию под `/yoga-platform/`.
3. Проверьте мобильное меню, RU/AZ/EN, один завершённый таймер, внешнее видео, установку и открытие без сети после первого онлайн-сеанса. Запишите модель, браузер, SHA и результат отдельно для каждого сценария.
4. Покажите владельцу изменения и результат. После разрешённого слияния дождитесь успешного развёртывания нужного SHA, сверки файлов и повторной браузерной проверки. Добавьте контрольную точку в панель.

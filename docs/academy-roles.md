# Первый администратор закрытой Академии

Применяется после установки миграции 00400 в отдельной тестовой среде. Управление ролями опирается на UUID пользователя Supabase Auth. Первый администратор назначается владельцем базы после подтверждения личности и адреса пользователя.

1. Откройте Authentication → Users и скопируйте UUID подтверждённого постоянного аккаунта администратора.
2. В SQL Editor нужного проекта подставьте этот UUID вместо текста в угловых скобках в запрос ниже. Выполняйте только после решения о выдаче полномочий. Запрос добавляет первую административную роль для подтверждённого, действующего аккаунта. Если результата нет, проверьте адрес, статус подтверждения и уже назначенные роли.
3. Зафиксируйте выданный UUID, дату и решение в закрытом журнале владельца. Событие в базе для SQL Editor может иметь пустое поле actor. Последующие назначения из админского интерфейса фиксируют текущий UUID, прежнюю и новую роль.

```sql
insert into public.restart_school_roles (user_id, role)
select u.id, 'admin'
from auth.users u
where u.id = '<UUID из Authentication → Users>'::uuid
  and u.email_confirmed_at is not null
  and u.deleted_at is null
  and u.is_anonymous is false
  and not exists (select 1 from public.restart_school_roles where role='admin')
on conflict (user_id) do nothing
returning user_id, role;
```

Роль ученика действует по умолчанию. Чтобы отозвать административную роль, другой проверенный администратор удаляет её запись. Записи дневника остаются доступны только владельцу. Чтобы сменить преподавателя программы, администратор меняет instructor_id на UUID назначенного преподавателя. История завершений ученика сохраняется при снятии зачисления.

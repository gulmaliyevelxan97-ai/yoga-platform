# Первый пилот с одним аккаунтом

Используется один согласованный адрес владельца. Адрес вносится только в список допуска изолированного проекта. Доступ к тестовой базе и создание аккаунта или отправка письма согласуются отдельно.

## Настройки стенда

- Выделенный проект Supabase, одно окружение HTTPS и точный URL возврата, оканчивающийся на `/app/`.
- Примените миграции 001–011 на выделенной базе. Проверьте отчёты installed_cloud и installed_school. Включите подтверждение почты и Before User Created Hook. До разрешения на регистрацию можно проверять решение hook напрямую в транзакции только для чтения.
- Запускайте `npm run build:pilot -- --staging`. Возьмите `RESTART_STAGING_PROJECT_REF` из панели проекта с именем `restart-staging`. Сборка сверяет этот идентификатор с `RESTART_SUPABASE_URL` до записи файлов. Передайте сборке URL изолированного проекта и его publishable key. Почтовые ключи и пароли базы остаются в настройках провайдера.
- Закрытый статический просмотр можно использовать для языка, темы, каталога, дневника и навигации до подключения Supabase. Для локальной PWA используйте localhost либо HTTPS.

## Сквозная проверка после разрешения

1. В профиле A зарегистрируйте единственный согласованный адрес, получите подтверждение и откройте ссылку в том же профиле. Выйдите и войдите заново.
2. Запросите восстановление в профиле A. Откройте письмо в этом же профиле. Проверьте экран восстановления и вход с новым паролем.
3. В профиле A сохраните синтетическую заметку, цель и практику. Войдите с тем же аккаунтом в отдельном браузерном профиле B, обновите данные и сравните записи. Измените заметку в B, обновите A и проверьте результат. Изоляция двух реальных пользователей проверяется на следующем этапе.
4. Пройдите [протокол PWA](samsung-pwa-test.md). Для облачных изменений проверьте сохранение черновика при потере сети и ручную повторную отправку.
5. Зафиксируйте SHA, адрес стенда и результаты. В журнале теста достаточно статуса письма и времени доставки. Не записывайте содержимое ссылки и пароль.

## Настройка Auth через Management API

Сценарий `scripts/configure-staging-auth.mjs` привязан к существующему проекту `restart-staging` и закрытому URL приложения. Он принимает авторизацию только из локально заданной переменной `SUPABASE_ACCESS_TOKEN`. Используйте защищённое окружение с разрешением на чтение и изменение Auth Configuration этого проекта.

```sh
node scripts/configure-staging-auth.mjs
node scripts/configure-staging-auth.mjs --apply
```

Первый вызов показывает ожидаемые изменения четырёх полей. Второй применяет их и сверяет состояние повторным запросом. Если уже настроен другой хук или дополнительные URL возврата, сценарий останавливается. Регистрация тестовых пользователей, подтверждение почты и доставка писем проверяются отдельно.

[Management API Supabase](https://supabase.com/docs/reference/api/v1-update-auth-service-config)

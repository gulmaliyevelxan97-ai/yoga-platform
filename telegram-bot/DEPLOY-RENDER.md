# RESTART на Render

Круглосуточный worker без публичного порта. Docker-образ использует Node.js 24, Blueprint настраивает один экземпляр и постоянный диск 1 ГБ. Ориентир за полный месяц — 7,25 USD: вычисления 7 USD и диск 0,25 USD. Проверь итоговую сумму в панели перед подтверждением. Дополнительные платные настройки не требуются.

## Запуск с телефона

1. После разрешения на публикацию конфигурации отправить подготовленную ветку `prototype/restart-telegram-cloud` в репозиторий RESTART. Ветка GitHub Pages `main` для запуска worker не используется.
2. В браузере открыть [панель Render](https://dashboard.render.com/), войти, выбрать **New → Blueprint** и подключить только репозиторий `gulmaliyevelxan97-ai/yoga-platform`.
3. Выбрать ветку с ботом и указать **Blueprint Path** `telegram-bot/render.yaml`. Проверить прогноз расходов, тип Background Worker и размер диска. Отключить автоматическую синхронизацию Blueprint, если обновления должны утверждаться вручную.
4. В поле **TELEGRAM_BOT_TOKEN** в панели Render вставить токен BotFather. Blueprint содержит только имя переменной. Доступ к значению оставлять только владельцу проекта. Нельзя отправлять токен в чат, сохранять в коде или в скриншотах. Если токен когда-либо был открыт другим, сначала перевыпустить его через BotFather.
5. Подтвердить создание сервиса только после согласования расходов. Убедиться, что другой процесс не запущен с этим токеном. Если у бота был webhook, код остановится и не будет его удалять.

## Контроль запуска

В разделе **Logs** дождаться `RESTART bot: long polling started.` и первой записи `RESTART bot: daily backup completed.`. В Telegram отправить боту `/start`, выбрать AZ и EN, открыть MIND, BODY, NUTRITION, LIFE и профиль. Установить напоминание на ближайшую минуту, включить его, закрыть Telegram и дождаться доставки. Отправить `/stop`, затем вручную перезапустить worker в Render и убедиться, что язык и отключённое напоминание сохранились. Автоматическое восстановление процесса и повторное подключение после сбоя проверяются при развёртывании. Одновременный второй запуск с тем же токеном в отдельном сервисе недопустим.

## Журнал, перезапуск и данные

- Render собирает stdout и stderr в **Logs**. Бот пишет о запуске, сбоях polling и резервном копировании, без токенов, ID чатов и текстов сообщений. Временные сбои Telegram обрабатываются с нарастающей задержкой. При остановке процесса открытый long polling прерывается.
- Блокировка ОС `flock` удерживается весь срок работы процесса и не пропускает второй запуск на том же диске. После остановки ядро освобождает блокировку. Один диск Render доступен одному экземпляру, старый экземпляр останавливается перед развёртыванием нового. Если Telegram обнаруживает конкурирующий polling с другого хоста, процесс завершится с ошибкой. Основной диск: `/var/data/restart-telegram/restart.sqlite`.
- SQLite создаёт согласованную копию при первом запуске и затем раз в день UTC. Сохраняются последние семь копий в `/var/data/restart-telegram/backups/`. Render также делает ежедневные снимки диска. Для восстановления базы использовать согласованную копию SQLite. Перед восстановлением остановить worker и сохранить текущие файлы базы, WAL и SHM. Восстановление требует доступа администратора. Снимки и SQLite-копии находятся в той же инфраструктуре, отдельное внешнее хранилище не подключено.
